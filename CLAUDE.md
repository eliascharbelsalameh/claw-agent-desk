# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Data layer, multi-agent pipeline and unattended scheduler for a NVIDIA Build a Claw Paris challenge entry: an "analyst desk" of independent open-weight LLM agents that debates and cross-checks before recommending a US-stock portfolio. `claw_agent_spec.md` is the full working spec — architecture, the verified per-role model table, data sources, the IEX-only volume caveat, and the build schedule. Read it before making design decisions; it's a living doc, and its section 9 still has open questions (deadline is Oct 2, 2026, so the schedule in section 8 is tight).

This repo lives locally (not on the Google Drive folder where the spec originated) because Drive's sync layer makes venvs, pip installs, and the on-disk cache this project uses painfully slow. The Drive folder (`NVIDIA Build a Claw - Paris/`) keeps a reference copy of the spec only — this repo is where the code lives.

## Commands

```
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Windows
# .venv/bin/python -m pip install -r requirements.txt     # if ever run on Linux (e.g. Oracle A1)

.venv/Scripts/python -m pytest              # full suite (all offline; includes headless app tests)
.venv/Scripts/python -m pytest -q tests/test_alpaca_client.py   # single file
.venv/Scripts/python -m pytest -k relative_volume                # by name

.venv/Scripts/python -m agents AAPL MSFT NVDA            # live macro/context agent run
.venv/Scripts/python -m agents AAPL --no-llm             # data only, no Build credits
.venv/Scripts/python -m agents AAPL --analysts analyst_1 analyst_2   # context + both analysts + cross-check + critic loop
.venv/Scripts/python -m agents AAPL --analysts analyst_1 analyst_2 --no-critic   # stop at the cross-check
#   also --no-bias / --no-technical to skip the gates on an agreed buy

.venv/Scripts/python -m agents.scheduler --once decision  # one decision cycle for the next session, log-only orders
.venv/Scripts/python -m agents.scheduler --once retry     # resume deferred stocks of the current session
.venv/Scripts/python -m agents.scheduler --paper-orders   # run forever (the deployed service); orders to the paper account

.venv/Scripts/streamlit run ui/streamlit_app.py          # the app: run the desk by hand, inspect every stage
```

The scheduler reads credentials from the process environment or `.env` only (unlike the app it doesn't read the Windows registry), so on Windows run it from a shell started after the `setx`, or load them first. Deployment on the Oracle A1 box: `deploy/README.md`.

The app loads missing credentials from the Windows user environment by itself (names only; values are never shown), so it works from any shell. `.streamlit/config.toml` binds it to `localhost` — keep it that way: the Run button spends Build credits and the trace viewer shows everything the agents saw and said.

A live run needs the credentials in the *process* environment — see Credentials below for why a shell may not have them.

Tests never hit real APIs — every client is exercised with a fake `session.request` object, so the suite runs without any credentials present.

## Credentials

All six credentials are **already set as Windows user-level environment variables** (not in `.env`): `ALPACA_API_KEY_ID`, `ALPACA_API_SECRET_KEY`, `FRED_API_KEY`, `FINNHUB_API_KEY`, `SEC_EDGAR_USER_AGENT`, `NVIDIA_API_KEY`. `.env.example` documents them; `.env` exists but its secret fields are deliberately blank (only non-secret base URLs / cache dir remain). `load_dotenv()` doesn't override already-set OS env vars, so the env vars win — nothing needs changing in code.

**Don't read, `cat`, or write credential values through a Claude Code session.** Claude Code's file-watcher diffs any tool-touched file back into the transcript when it changes on disk, which already leaked (and forced rotation of) two keys during setup. Verify presence without exposing values, e.g.:

```
powershell -c "[Environment]::GetEnvironmentVariable('NVIDIA_API_KEY','User').Length"
```

Note that a shell started *before* a `setx` won't see the new value — an existing session's Bash tool may report a var as unset when it's actually set. Read `HKCU\Environment` (via PowerShell or Python's `winreg`) to check reliably, or have one-off live scripts load from there directly.

## Architecture

`data_layer/` is a set of thin, independent clients for each data source in the spec (section 5), sharing plumbing so retry/caching behavior is identical everywhere rather than reimplemented per client:

- `http_utils.request_with_retry` — every outbound HTTP call goes through this. Retries on 429/500/502/503/504 and on dropped connections (`requests.ConnectionError`; Build closes connections under load) with exponential backoff + jitter, honoring a numeric `Retry-After` header on 429s instead of guessing. Read timeouts are deliberately not retried. This is the "must have: retry with backoff on 429" requirement from the spec, applied to all data calls, not just LLM calls.
- `cache.DiskCache` — dependency-free JSON-file cache with a per-entry TTL, keyed by URL+params. Callers pick the TTL per call site (e.g. EDGAR's ticker→CIK map caches for a week, Finnhub news for 15 minutes) — there's no single global policy because "cache everything that changes slowly" (spec section 5) means different things per source.
- `base_client.BaseClient._get_json` — wires the above two together (check cache → retry-aware GET → cache the result) so each client only implements URL-building and response shaping, not request mechanics.

Per-source clients, each a thin subclass of `BaseClient`:

- `alpaca_client.AlpacaClient` — bars (`get_bars`), a `get_bars_4h` that tries Alpaca's native `4Hour` timeframe and falls back to aggregating `1Hour` bars via `aggregate_bars` if the API rejects it (spec flagged native 4H support as unverified), a `get_relative_volume` helper that implements the spec's IEX-volume rule directly (section 6: never trust absolute IEX volume, compare against a rolling baseline instead), `get_clock` (Alpaca's market clock; `session_in_progress(bar, clock)` tells whether a daily bar is today's still-running session — while it is, `get_relative_volume` compares the last *completed* session and reports the partial one separately as `in_progress_volume`, since a half-day's volume against full-day averages read as falsely low all morning), and paper-trading account/order methods (`get_account`, `list_positions`, `submit_market_order`, `get_order_by_client_id`, `get_calendar`). Bars are **split-adjusted** (`adjustment="split"`): raw bars put NFLX 94% below its "52-week high" across its 10-for-1 split (live, Sept 26). `submit_market_order` is a POST through the same retry as everything else, so it takes a `client_order_id` — a repeat is rejected by Alpaca instead of becoming a second order.
- `fred_client.FredClient` — macro series observations.
- `edgar_client.EdgarClient` — ticker→CIK resolution (cached a week), filings (`get_company_submissions`), fundamentals (`get_company_facts`). Enforces SEC's ~10 req/s fair-access limit via an internal rate limiter, and refuses to run without `SEC_EDGAR_USER_AGENT` set — there's deliberately no hardcoded default contact, since the challenge entry may end up public.
- `finnhub_client.FinnhubClient` — company news and the earnings calendar (`get_earnings_calendar`: report dates with consensus EPS/revenue estimates and, once reported, actuals; the free plan lists about a month back and months ahead — checked live Sept 26). The free plan doesn't reliably serve candles, so don't add a prices method here — use Alpaca. Tags every news item with `age_hours` on the way out since the staleness check downstream needs that.
- `llm_client.LlmClient` — NVIDIA Build chat-completions client (`chat_completion`, `complete_text`). Same retry/backoff as every other client via `request_with_retry`, plus client-side per-model rate pacing (`DEFAULT_RPM_LIMIT = 40`, the only figure Build confirms, applied to every model as a conservative default). `AGENT_MODELS` maps each pipeline role (macro, analyst_1, analyst_2, critic, bias_1, bias_2, technical) to a primary model, per the spec's "independent failure modes" design choice (spec section 4); `AGENT_MODEL_BACKUPS` gives each role ordered backups and `role_models(role)` returns primary + backups. `ModelHealth` (shared default `DEFAULT_MODEL_HEALTH`) remembers models that failed a call and orders them last for `MODEL_COOLDOWN_SECONDS` (15 min) so later calls don't each wait out a dead endpoint; `chat_completion(max_retries=...)` lets callers shorten the connection-retry budget. Two gotchas worth knowing before touching this file:
  - **Verifying a model id needs a real call.** `GET /v1/models` lists plenty of ids that then 404 with "Not found for account", and two of the original picks were 410 Gone (end of life). Neither build.nvidia.com's catalog page nor the per-model `docs.api.nvidia.com` reference pages were reliable. All seven current ids were confirmed with an actual `chat_completion` (Sept 2026) — see spec section 4 for the table and what each replaced.
  - **Most of these are reasoning models** (hidden chain-of-thought before visible content), so a small `max_tokens` yields `finish_reason: "length"` with empty `content`, and they're slow — `DEFAULT_TIMEOUT` is 120s here versus 15s elsewhere in the data layer, because `openai/gpt-oss-20b` alone needed ~90s. Nemotron models take `chat_template_kwargs={"enable_thinking": False}` to skip reasoning entirely (one-line prompt: 59s → 2s); use it for roles that only summarize.
  - **Calls stream by default, and must.** Build's gateway kills any connection that sends no bytes for 60s, so a non-streaming call to a reasoning model dies at 60s regardless of `DEFAULT_TIMEOUT` (reproduced repeatedly, Sept 2026). `chat_completion` streams and reassembles the chunks into the normal non-streaming response shape (reasoning goes to `message.reasoning_content`), and retries dropped/truncated streams `STREAM_RETRIES` times. Pass `stream=False` only for calls known to finish fast.
  - **Build output quality is not guaranteed.** Live, 2 of 3 briefings from the macro model degenerated mid-text into "The The The…" / ",,,,,,," — both on calls whose first stream had dropped. Any agent that forwards LLM text should validate its shape before passing it on (see `agents.macro_agent.briefing_problems`).

`agents/` holds the pipeline agents (spec section 3), built on the data layer:

- `llm_json.request_json` — the shared "ask a model for one JSON object" loop every structured-output agent uses: call → log the raw reply (`llm_response`, including `reasoning_content` and `usage`) → parse with `extract_json_object` (which applies `repair_json_quotes` when the JSON doesn't parse) → caller-supplied `validate` → on failure, exactly one correction turn. Returns a `JsonReply` whose `call_failed` separates "the call failed" from "the model answered unusably". It takes an ordered list of `models` and fails over on either kind of failure (fresh conversation per model, `fallback` trace event), with `exclude` for models that would break independence and `health` for cooldown ordering. Retry budget: the last model not known to be down gets `request_with_retry`'s full budget, every other model `BACKUP_CONNECT_RETRIES` (1 retry, so a dead endpoint fails over in ~2 min instead of ~7), and a cooling model only ever the short probe. `JsonReply.model` is the model that actually answered; `fallbacks` lists the ones that failed first. New agents should use this rather than their own loop.
- `trace.TraceLogger` — append-only JSONL log of every agent's input and output with a UTC timestamp (spec section 3: the demo needs the back-and-forth, not just the final call). One line per event; every agent should log through this.
- `macro_agent.MacroContextAgent` — step 1 of the pipeline. `run(symbols)` gathers FRED macro (once, shared), Alpaca daily/4H bars + relative volume, EDGAR filings + fundamentals, and Finnhub news per symbol into a `StockContext`, then asks `AGENT_MODELS["macro"]` (thinking off) for a neutral factual briefing that is explicitly forbidden from opinions or recommendations. `StockContext.to_prompt()` is what downstream analysts consume: the briefing plus the full source facts, labeled as authoritative over the briefing. Design points:
  - Every source failure becomes a line in `StockContext.data_gaps` instead of an exception, so a 2-day run degrades rather than crashes; analysts are told what's missing.
  - The briefing is validated (`briefing_problems`: degenerate repetition, missing sections), retried once with a fresh call, then dropped to a facts-only packet with a gap recorded. Rejections are logged as `briefing_rejected`.
  - Finnhub's company-news feed is keyword-matched and mostly noise (live: 115–202 of ~130–220 weekly items for AAPL/MSFT/NVDA didn't mention the company), so `filter_news` keeps only items mentioning the ticker or the EDGAR-registered short name. Done deterministically because the no-thinking model miscounted when asked to filter.
  - Fundamentals take the most recent period across all candidate XBRL tags (companies switch revenue tags in both directions — NVDA's current revenue is under `Revenues`, AAPL/MSFT's under the ASC 606 tag), and anything older than `FUNDAMENTALS_STALE_DAYS` is flagged as a gap. A 10-K period-end yields the fiscal-year figure (no separate Q4 is tagged), so `period_start`/`period_end` always travel with each value.
  - Each fundamental also carries the same-period year-ago value and `yoy_pct_change` (quarter vs quarter, fiscal year vs fiscal year, searched across all candidate tags). Without it, analysts asserted "earnings growth" from a single quarter.
  - `facts()` always includes `limitations` (`DESK_LIMITATIONS`): what the desk never provides — no valuation data, no forward guidance, only latest-vs-year-ago fundamentals, unverified news, IEX-only volume. Identical for every stock and run (a disclosure, not a judgment), and deliberately separate from `data_gaps`, which is only what failed to load this run.
  - Rates and spreads get an absolute year-over-year change; only CPI gets a percentage change (`PERCENT_CHANGE_SERIES`).
  - The market clock is read once per run (`market_clock`); while today's session is running, `price.latest_bar_in_progress` is true and a `note` says `last_close` is the latest intraday price. An unreadable clock is a data gap for every stock.
  - Since Sept 26 the packet also carries three blocks the desk computes itself (`computed_facts.py`, below): `valuation`, `technicals` and `earnings`. Daily bars go back `DAILY_LOOKBACK_DAYS` (400) for the 200-day average and 52-week range; SPY's bars (`BENCHMARK_SYMBOL`) are fetched once per run in `prepare()` for the relative moves; 1-hour bars (`bars_1h`, like `bars_4h` kept out of `facts()`) feed the technical agent. `DESK_LIMITATIONS` was rewritten to say what is still missing (forward multiples, company guidance, IEX prices and volume), not what used to be.
- `computed_facts` — deterministic, traceable numbers added because the analysts kept pointing at what the packet lacked (38 of 43 holds in the Sept 25–26 tests cited missing valuation or forward data): trailing-twelve-month revenue/net income/EPS from SEC filings (`trailing_twelve_months`: fiscal year + this year-to-date − last year's same year-to-date, never mixing tags) combined with the price into market cap, P/E and price-to-sales (share count = latest quarter's diluted weighted-average shares, because EDGAR's cover-page count is missing for multi-class companies like META and GOOGL); RSI(14), 20/50/200-day averages, ATR(14), 52-week range and change vs SPY from daily bars; the next and latest earnings report. Cross-checked live against Finnhub's own figures (P/E within ~3%, 52-week ranges matching). No interpretation labels ("overbought", "cheap") — what the numbers mean over 2–5 days is left to the analysts.
- `analyst_agent.AnalystAgent` — step 2. One instance per role (`analyst_1`, `analyst_2`); `analyze(ctx)` sends `StockContext.to_prompt()` to that role's model and returns an `AnalystVerdict`: `recommendation` (buy/hold/avoid), `confidence`, `thesis`, `drivers`, `risks`, `evidence`, `data_concerns`. Design points:
  - `revise(ctx, own, other, assessment=..., challenges_to_me=..., challenges_to_other=..., review_round=n)` is the critic-loop re-vote: same packet plus both previous verdicts (via `AnalystVerdict.brief()`, which deliberately omits the model name and the confidence) and the critic's challenges. The prompt says to change the recommendation only for a real error, an ignored fact, or an unanswerable argument, and not to change it just to agree. Returns a new verdict with `review_round`, `previous_recommendation` (so `changed` is derived, not self-reported) and `response_to_critique`: one `{point, accept, reason}` per challenge, parsed leniently by `parse_critique_responses` (free text or a `{point: reply}` mapping, both seen live, keep `accept=None`), with `challenges_accepted`/`challenges_rejected` counts. The re-vote prompt says the critic is another model and can be wrong, and asks the analyst to reject challenges the facts don't support: in the first live run, before this, analysts accepted 24 of 27 challenges and rejected none.
  - Structured JSON so the cross-check compares `recommendation` fields, not prose. Invalid replies get one correction turn (the model sees its reply and the validation error); after that the verdict has `error` set. **A failed verdict must be treated as "no pick", never as agreement.**
  - **JSON quote repair.** `nemotron-3-super` intermittently drops the quotes on string values — every `"why"` in a reply at once (`"why": Indicates growth.`), or a list item's closing quote — in 5 of 38 replies on Sept 25, and the correction turn reproduced the identical error every time. When a reply doesn't parse, `repair_json_quotes` adds the missing quotes (whole lines only, no word changed), and the result must still parse and validate. Repairs are logged as `verdict_repaired` and kept in `AnalystVerdict.json_repairs`. All 5 real failures recovered, every string verbatim from the original. Build's structured-output options were tested: `nvext.guided_json` is rejected (400 unknown field); `response_format: {"type": "json_object"}` is accepted but not adopted — too few samples to show it prevents the bug, and it roughly halved nemotron's reasoning length.
  - Every evidence item cites a path into the facts (`price.change_20d_pct`, `news[2].headline`), and `check_evidence` resolves it deterministically: `matches_source`, `wrong_index` (real value at another list position — seen live), `mismatch` (with the `actual` value), or `unknown_path`. This catches quoted-number hallucinations; it cannot catch uncited prose claims, which is why the context has to carry the numbers (year-ago values) that make claims checkable. **The check confirms quotes, not truth**: the status was called `verified` until Sept 25, when the critic read a news item's `verified` status as "confirmed fact" and pushed an analyst toward buy on it. Any prompt that shows statuses to a model must include `EVIDENCE_STATUS_NOTE`.
  - **Decided:** long-only, real shares — no shorting, derivatives, leverage or negotiated deals; "avoid" means not holding, never shorting. **Decided:** `HORIZON` is the next 2–5 trading days — a forward projection judged only from data available now, chosen so the ~2-day paper run can test the calls. The prompt states only the window, not what to weigh at that range.
  - **Models (Sept 25, 2026):** `analyst_1` is `google/gemma-4-31b-it`, replacing `openai/gpt-oss-20b` (failed 5 of 15 calls, 65–400s per answer, left `data_concerns` empty). Candidates screened side by side on frozen contexts: only gemma answered reliably; `glm-5.3`/`glm-5.3-flash`/`kimi-k3` mostly exhausted connection retries; `kimi-k2.6`, `mistral-large-2-instruct`, `palmyra-fin-70b-32k` return 404 on this account. Nemotron models were excluded to keep analyst_1 independent of analyst_2.
  - **Temperature 0** (`ANALYST_TEMPERATURE`). Over 3 repeats on identical input, gemma returned identical verdicts and confidences; `nemotron-3-super` still split 2–1 on MSFT and NVDA, so disagreements remain for the critic loop to resolve.
  - To watch: gemma said buy on all three test stocks at 0.75–0.85 and lists fewer `data_concerns` (2–3 vs 4–5 for nemotron). Three momentum large caps is too few to call it a bias, but an always-buy analyst would reduce the cross-check to analyst_2 alone — re-check on a wider stock set.
  - **Decided Sept 26, 2026: one symmetric bar.** The prompt used to say "if you disagree, the stock is not picked, so only recommend buy when the evidence genuinely supports it" and defined hold as "no strong case either way" — a one-sided brake on top of the desk's own (strict match, critic on every buy). Now: weigh drivers against risks and say where the balance leans for a holder over the horizon — buy if toward a gain, avoid if toward a loss, hold if balanced or too thin; "Buy and avoid take the same bar." Caution lives in the desk's structure, where the trace shows it.
  - `analyze(allow_backup=False)`: only the role's primary answers by default, and `revise` runs only on the model that wrote the verdict (a re-vote from another model would be a different analyst). When the model can't be reached the verdict has `call_failed=True` and the pipeline defers the stock (below); `call_failed=False` with `error` means it answered unusably (final).
- **Backups, deferral and independence at runtime (policy of Sept 26, 2026).** Every agent takes `models`/`health` (default: the role's `role_models` and the shared health) or a pinned `model`, and records the model that actually answered (`model`), the role's `primary_model`, and `fallbacks`. *Analysts don't fail over*: a Build failure defers the stock instead (retried from the failed step next pass), because a backup that judges differently would silently change the decision — muse-glimmer, analyst_1's backup, said buy 0 times in 23 verdicts before the prompt change. Analyst backups are allowed only after the primary has been unreachable for `pipeline.ANALYST_BACKUP_AFTER` (3 h, tracked across cycles in `ModelOutages`). The macro briefing, the critic, the bias agents and the technical agent still fail over (they don't vote); the critic and the bias agents exclude the models the analysts actually used, and bias_2 the model bias_1 used. The two analysts' candidate lists share no model (enforced by a test), which is also what lets them run in parallel. The macro briefing sends the Nemotron thinking-off flag only to `nvidia/nemotron*` models (`briefing_params`).
- `cross_check.cross_check(a, b)` — the gate after the analysts. A deterministic rule, not an LLM call, returning a `CrossCheckResult` (`outcome`, agreed `recommendation`, human-readable `reason`, both verdict summaries) and logging it as a `cross_check`/`decision` trace event. Outcomes: identical recommendations → `agree`; buy vs hold → `critic`; buy vs avoid, hold vs avoid, a verdict that came back unusable, or both analysts on the same model → `abort`; an analyst whose model couldn't be reached → `deferred` (Sept 26: a Build outage is not a decision; never counted as agreement). Confidence is carried for the trace but never affects the outcome. Replayed on the 9 real temperature-0 verdict pairs: 5 agree (buy), 3 critic, 1 abort (failed call).
- `critic_agent.CriticAgent` — step 3's challenger. `review(ctx, verdicts, review_round)` returns a `Critique`: an `assessment` of where the two analyses agree and diverge, plus up to `MAX_CHALLENGES_PER_ANALYST` (3) `challenges` per analyst, each `{to, point, why}` with an optional cited `fact`/`value` that goes through the same `check_evidence` as analyst evidence. **The critic never gives its own recommendation** — a voting critic would turn the desk into a majority vote and bypass the strict two-analyst match. Prompted to hold both analysts to the same standard and to leave a sound analysis unchallenged rather than invent weak points.
- `critic_loop.run_critic_loop` — runs when `needs_critic(cross_check_result)` returns a trigger: `split` (buy vs hold, per the Sept 25 decision) or `agreed_buy` (spec section 3: challenge before anything is decided; a buy is the only outcome that opens a position; switch off with `CHALLENGE_AGREED_BUYS`). Agreed hold/avoid skip it. Each round = critic review → both analysts `revise` → `cross_check` on the revised pair: agree ends it (the agreed recommendation may differ from the original), a buy/hold split gets another round up to `MAX_ROUNDS` (2) and then aborts, a contradiction or failed re-vote aborts, and a failed critic call aborts (an unchallenged buy is what this step exists to prevent). Logs `start`/`round`/`final` events under `critic_loop`; each round costs 3 LLM calls. Since Sept 26 a call that can't be reached (every critic candidate, or an analyst's re-vote) makes the loop `deferred` rather than aborted: `CriticLoopResult.resume` keeps the round, the verdicts going into it, the critique if it came back and any re-vote that did, and `run_critic_loop(resume_from=...)` repeats only the failed calls. `CriticLoopResult.verdicts` holds the full final verdicts for the stages after it.
- `bias_agent` — step 4. `BiasAgent.review` (bias_1 muse-glimmer, bias_2 mistral-nemotron) scores the news sentiment itself (Finnhub's is paid) and answers three named checks — `news_driven`, `stale_news`, `trend_chasing` — with pass or flag; never a recommendation. `bias_gate` runs only on an agreed buy: **a veto needs both agents to flag** (mirroring the strict two-analyst match: no single model decides, spec section 1), a single flag is kept in the reason, an unreachable agent defers (the other's check is kept for the retry), an unusable answer fails the gate.
- `technical_agent` — step 5, last. On an agreed buy that passed the bias gate, `TechnicalAgent.time_entry` reads the 4-hour then the 1-hour bars (plus the facts) and answers `enter` (buy at the next open) or `wait` (not today; re-examined at the next daily cycle) with the 4h trend and support/resistance. It never revisits the pick and can't create a buy; the prompt asks for a specific chart-based reason to wait, "not for general uncertainty". Evidence can cite `chart.bars_1h[i]` paths.
- `portfolio` — step 6, the output. `Decision.from_run` is the desk's final word on one stock (outcome, agreed recommendation, reason, price, and the gates' results); `Portfolio.plan/execute/record` turns decisions into paper orders under rules stated in the module: only an agreed, ungated buy opens a position (10% of equity, whole shares, max 8, no margin); a desk position is sold on an agreed avoid or when its 5-session horizon ends (an agreed buy restarts it); everything else changes nothing; positions the desk didn't open are never touched. Orders carry `client_order_id` = `desk-{session}-{symbol}-{side}`, and a rejected repeat is looked up and recorded as the same order. `dry_run` (the default outside the deployed scheduler) records without sending.
- `state.DeskState` — the scheduler's memory in one JSON file (`state/desk_state.json`, gitignored, written atomically): deferred runs (`pending`, full `SymbolRun` dicts), `outages`, the desk's own `positions`, and rolling logs of `decisions` and `cycles`.
- `scheduler.DeskScheduler` — the unattended loop (`python -m agents.scheduler`). `tick()` reads Alpaca's clock: once per trading session, at `DECISION_TIME_ET` (08:00 ET, before the open — the latest daily bar is a finished session and Build was quieter then), a decision cycle runs the full desk on the watchlist plus every stock the desk holds, `WORKERS` (3) stocks at a time, and sends the portfolio's orders (queued for the open); every `RETRY_EVERY` (30 min) until `RETRY_UNTIL_ET` (15:00 ET) a retry pass resumes deferred stocks with the morning's context; deferred stocks from an earlier session are dropped (the next cycle re-analyzes them fresh). Every pass is summarized in the trace and the state, with LLM calls, errors and `failures_by_hour`. Restart-safe: the state records the session already decided, and order ids make replays harmless.

- `pipeline.DeskPipeline` — the one place the stages are sequenced; the CLI (`agents/__main__.py`), the Streamlit app and the scheduler all run it. `DeskPipeline.from_settings(use_llm=..., analyst_roles=..., run_critic=..., run_bias=..., run_technical=..., challenge_agreed_buys=..., max_rounds=..., outages=...)` builds the live desk; `use_llm=False` is data only. `run(symbols, on_event)` fetches macro, the clock and SPY once (`MacroContextAgent.prepare`), then per stock: context → both analysts in parallel → cross-check → critic loop when triggered → bias gate and technical agent on an agreed buy, calling `on_event(stage, symbol, payload)` after each stage (`context`, `verdict`, `cross_check`, `critic_loop`, `bias`, `technical`, `done`). `run(..., workers=n)` processes n stocks at once (the scheduler); events then come from worker threads, so the app keeps the default of 1. Returns one `SymbolRun` per stock (`outcome`/`recommendation` = the critic loop's if it ran, else the cross-check's; `deferred` when any stage is waiting on a Build failure; `to_dict`/`from_dict` for the state file). `resume_symbol(run)` continues a deferred run from its failed step.

`ui/` is the Streamlit app. `streamlit_app.py` renders a run live (per-stage progress, then a summary table and per-stock tabs: context metrics — price, relative volume, RSI, vs SPY, P/E, next earnings — gaps, briefing and the computed blocks; both verdict cards with model/backup, evidence statuses and data concerns; the cross-check; every critic round with challenges and accept/reject responses; the bias gate with both checks; the entry timing; the LLM calls/tokens/fallbacks the run cost), a **Retry deferred** button that resumes deferred stocks from their failed step, a **Desk state** tab that reads the scheduler's state file (positions, deferred stocks, decisions, passes), and a trace viewer that replays any `logs/*.jsonl` without spending credits. Finished stocks survive a mid-run interaction (Streamlit reruns the script on any widget change). `support.py` holds the Streamlit-free helpers (ticker parsing, credential presence, the Windows user-env loader, trace summaries) so they can be unit-tested. Tests drive the real app headlessly with `streamlit.testing.v1.AppTest`, with every live component swapped for the fakes in `tests/fakes.py` (set `CLAW_DESK_NO_REGISTRY` and `CLAW_DESK_LOG_DIR` there so tests never read real credentials or write to `logs/`).

`deploy/` holds the Oracle A1 deployment: `setup.sh` (Python 3.11+, venv, empty `.env` with mode 600 — credentials are typed on the server, never through a session), a systemd *user* unit running the scheduler with `--paper-orders`, and `README.md` with the steps (dry run first, then the service; the app only through an SSH tunnel).

`config.Settings` / `get_settings()` load everything from environment variables (OS env vars, falling back to `.env`) and provide a `.require(field)` that raises `ConfigError` with a clear message instead of the client failing deep inside a request. Every client accepts an optional `Settings`, `requests.Session`, and `DiskCache` in its constructor for testability — tests always inject a fake session and skip real network calls.
